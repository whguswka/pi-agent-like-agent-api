| 경로 | 내용 | 출처 |

| `profiles/` | 설정 템플릿(LLM 주소 등 JSON), 기본 지침(Markdown)과 공통 pi 확장(`common/.../guard.ts`: 위험 명령 실행 전 확인, `modes.ts`: 계획·확인 모드, `undo.ts`: 고친 파일 되돌리기, `memory.ts`: 지침 파일에 기억할 것 적기·작업 기록, `files.ts`: 입력창 @파일 고르기·내용 붙이기, `notify.ts`: 작업 끝 알림, `kit.ts`: 도움말·상태 요약·설치된 라이브러리 설명 찾기·LLM 이 사용자에게 고르기 창으로 묻기(`ask_user`), `wiki.ts`: LLM 위키(사용자가 정한 폴더의 마크다운 페이지를 찾기·읽기·쓰기, 쓰기는 그 위키의 pages/ 아래와 작업 방식을 배울 때의 사용자 지침 파일), `hooks.ts`: 문서 규칙(새 문서를 작업 폴더의 문서 목록에 링크, 많으면 묻기)·완료 점검(프로젝트에 적힌 점검 명령을 사용자 동의 뒤 실행)·문법 확인(고친 Python·JSON·YAML 파일의 문법만 확인)·훅 켜고 끄기, `rules.ts`: 팀 규칙(저장소에 있는 다른 코딩 도구의 지침·규칙 파일 읽기)) | 자체 작성 |
| `prompts/`, `skills/` | 기본 명령(프롬프트 템플릿) 5개와 기본 스킬 9개. Markdown 문서이고, `project-harness` 스킬의 `examples/` 에는 팀 점검 스크립트 예(.py)와 설정 예(.json)가 있음 (설치할 때 사용자 설정 폴더에 복사. 예는 실행하지 않음) | 자체 작성 |
| `tests/`, `docs/` | 단위 테스트, 문서 | 자체 작성 |

자체 작성 부분은 모두 사람이 읽을 수 있는 소스입니다 (압축·난독화 없음).

## 3. 동작 방식
- pi 는 사용자가 노트북 터미널에서 지시한 작업을 LLM 과 주고받으며 수행합니다. LLM 이 요청한 도구(파일 읽기·쓰기·수정, 셸 명령 실행)를 **노트북 안에서 사용자 계정 권한으로** 실행합니다. 이는 코딩 에이전트의 기본 기능입니다.
  - 되돌리기 어려운 작업(폴더 삭제, `git push`, `kubectl delete`, 패키지 제거, `sudo`, 작업 폴더 밖 파일 쓰기, GitLab 등 원격 저장소를 바꾸는 명령·API 호출, S3 등 객체 저장소 지우기, DB 행 지우기(`DELETE FROM`), 사용자가 읽기 전용으로 정한 폴더(`guard_readonly`, 2026-10-26)를 바꾸는 명령·파일 쓰기 등)은 실행 전에 사용자에게 확인을 받고, 거부하면 실행하지 않습니다 (확장 `guard.ts`).
    실행하는 셸 스크립트 안의 원격 작업(`git push` 등)은 그 파일을 읽어 확인합니다 (2026-10-22).
  - **작업 기록 (2026-10-21, 확장 `memory.ts`):** 요청이 끝날 때마다 요청 글, 바꾼 파일 이름, 실행한 명령, 답의 앞부분을 작업 폴더별 파일(`~/.pi/agent/work-log/`, 사용자 홈)에 남기고, 같은 폴더에서 새 세션을 시작하면 그 요약(1200자 안)을 LLM 에 보내는 지침에 넣습니다. 이메일·전화번호·계좌번호 모양 번호는 빼고 남기고, 비밀번호·토큰으로 보이는 글은 남기지 않습니다. 사용자가 끌 수 있습니다(`/recall off`). 따로 네트워크에 접속하지 않습니다.
  - **설치된 라이브러리 설명 찾기 (2026-10-21, 확장 `kit.ts`):** LLM 이나 사용자가 요청하면 이미 설치된 Python 패키지를 불러와(import) 버전·설명 글을 읽고, 사용자 폴더(`~/pi-docs`)의 문서에서 맞는 줄을 찾아 그 결과를 LLM 에 보냅니다. 인터넷에 접속하지 않고 패키지를 설치하지 않습니다.
  - **작업 방식 배우기 (2026-10-20, 확장 `wiki.ts`):** LLM 위키를 켠 사용자가 쓰면, LLM 이 위키를 쓰면서 함께 적은 일하는 방식(최대 10줄·1200자)을 사용자 지침 파일(`~/.pi/agent/AGENTS.md`)의 정해진 부분에 자동으로 적습니다. 고치기 전 내용을 남기고 되돌릴 수 있으며(`/wiki lessons undo`), 끄거나 제안만 받을 수 있습니다(`/wiki lessons off`·`propose`).
  - **문서 규칙 (2026-10-22, 확장 `hooks.ts`):** 작업 폴더에 새 Markdown 문서가 생기면, 그 링크 한 줄을 프로젝트의 문서 목록 파일(`docs/INDEX.md`)에 확장이 직접 더합니다.
    목록 파일이 없으면 사용자에게 묻고 만듭니다. 한 요청에 새 문서가 많거나 이력·계획 문서가 겹치면 만들기 전에 사용자에게 묻고, 읽기는 막지 않습니다.
    `/hooks` 로 이 규칙과 사용자가 만든 확장을 켜고 끄며, 위험 명령 확인(`guard.ts`)이 꺼져 있으면 시작할 때와 상태 줄에 알립니다. 네트워크 사용 없음.
  - **완료 점검 (2026-10-26, 확장 `hooks.ts`):** 프로젝트에 팀이 둔 점검 목록(`.pi/checks.json`)이 있으면, 요청이 끝날 때 그 요청에서 바뀐 파일이 목록의 조건에 맞을 때
    목록에 적힌 명령(팀의 점검 스크립트 등)을 **사용자 계정 권한으로 실행**하고, 실패하면 출력 끝부분을 LLM 에 보내 고치게 합니다 (요청마다 한 번, 되풀이하지 않음).
    저장소에 적힌 명령이므로 프로젝트·명령마다 처음 한 번 사용자에게 실행해도 되는지 묻고(답은 `~/.pi/agent/doc-rules.json`), 명령마다 시간 제한(기본 120초, 최대 600초)이 있습니다.
    계획 모드와 물어볼 수 없는 실행(`pi -p`)에서는 실행하지 않고, 사용자가 끌 수 있습니다(`/hooks off checks`). 확장은 네트워크를 쓰지 않습니다 (점검 명령이 하는 일은 그 저장소의 명령에 따름).
  - **팀 규칙 (2026-10-28, 확장 `rules.ts`):** 작업 폴더부터 위로 git 저장소 맨 위까지에서, 팀이 다른 코딩 도구용으로 둔 지침·규칙 파일(`.github/copilot-instructions.md`, `.github/instructions/`, `.cursor/rules/`, `.claude/CLAUDE.md`, `.pi/rules/`)과
    사용자 폴더의 `~/.pi/agent/rules/` 를 **읽기만** 하고, 그 내용을 LLM 에 보내는 지침에 넣거나 해당 파일·명령을 다룰 때 도구 결과에 붙입니다.
    홈 폴더(다른 도구의 개인 설정)는 읽지 않습니다. 사용자에게 알린 규칙 목록의 지문만 `~/.pi/agent/rules-seen.json` 에 남기며, 사용자가 끌 수 있습니다(`/hooks off rules`). 네트워크 사용 없음.
  - **문법 확인 (2026-10-28, 확장 `hooks.ts`):** LLM 이 쓰거나 고친 `.py`·`.json`·`.ipynb`·`.yaml` 파일을 읽어 문법만 확인하고, 깨졌으면 줄 번호를 LLM 에 알립니다.
    Python 파일은 실행하거나 불러오지 않고 구문 분석(`compile(…, "exec", ast.PyCF_ONLY_AST)`)만, YAML 은 구조 읽기(`yaml.parse`)만 합니다. 사용자가 끌 수 있습니다(`/hooks off syntax`). 네트워크 사용 없음.
  - **사용자에게 묻기 (2026-10-28, 확장 `kit.ts` 의 `ask_user` 도구):** LLM 이 사용자만 정할 수 있는 것을 고르기 창으로 묻고, 사용자가 고르거나 적은 답을 LLM 에 보냅니다. 화면이 없는 실행(`pi -p`)에서는 묻지 않습니다.
  - 사용자가 고르면 더 조심스럽게 쓸 수 있습니다 (확장 `modes.ts`): 계획 모드는 읽기와 계획서 파일(작업 폴더의 `docs/plans/` 아래나 이름에 '계획'·`plan` 이 든 `.md`) 쓰기만 하고 계획을 세워 사용자가 승인한 뒤에 실행하고, 확인 모드는 파일을 바꾸거나 명령을 실행할 때마다 바뀌는 내용을 보여 주고 확인을 받습니다. pi 가 고친 파일은 `/undo` 로 되돌릴 수 있습니다 (확장 `undo.ts`).
- LLM 은 사용자가 설정 파일(`~/.pi/agent/models.json`)에 적은 OpenAI 호환 API 서버입니다. pi 는 지침, 요청, 읽은 파일 내용, 명령 결과를 그 서버로 보내고 답을 받습니다.
- 설치는 사용자 홈 아래(`~/tools/pi`, `~/.pi/agent`)에만 파일을 두고, 셸 시작 파일(`~/.bashrc`, `~/.profile`)에 PATH 한 줄을 더합니다. 관리자 권한이나 시스템 영역 쓰기는 없습니다.
- 공용 확장(`profiles/common`)은 이 키트의 바탕인 pi-agent-like-agent 와 같은 파일입니다. 그 저장소에서 웹 채팅 연결 프로그램을 거쳐 원격 노트북의 파일을 다루던 분기(`lib/relay.ts` 의 원격 분기, 127.0.0.1 로만 접속)가 코드에 남아 있지만,
  이 키트에는 그 분기를 켜는 확장과 연결 프로그램이 들어 있지 않아 실행되지 않습니다.

## 4. 네트워크 접속
| 구성요소 | 접속 대상 | 비고 |
|---|---|---|
| pi | 사용자가 설정 파일(`~/.pi/agent/models.json`)에 적은 LLM API 주소 | 그 외 자동 접속은 끔 (아래). 노트북의 프록시 환경변수를 따름 |
| 실행기·확장 (자체 작성) | 없음 | 외부 주소로 접속하지 않음 |

- 자동 네트워크 활동을 끕니다: 실행기가 `PI_OFFLINE=1`(모델 목록 갱신 등 자동 네트워크 활동 끔)과 `PI_SKIP_VERSION_CHECK=1`(pi.dev 최신 버전 확인 끔)을 설정하고, 설정 템플릿에 `enableInstallTelemetry: false`(익명 설치·업데이트 통계 끔)를 넣었습니다. 각 설정의 의미는 pi 공식 문서(`runtime/docs/`) 기준입니다.

## 5. 원본 동일성 확인 방법

확인 절차 (인터넷 PC):
1. 배포 주소에서 `.tgz` 를 내려받아 [THIRD-PARTY-NOTICES.md](../THIRD-PARTY-NOTICES.md) 의 sha512 와 비교합니다.
2. 압축을 풀어 [runtime-SHA256SUMS.txt](runtime-SHA256SUMS.txt) 의 파일별 sha256 과 비교합니다.
   `runtime/` 는 pi 패키지의 `package/`, `runtime/node_modules/<이름>/` 은 해당 패키지의 `package/` 에 대응합니다.

## 6. 백신 검사 관련
pi 는 셸 명령을 실행하는 코딩 에이전트이고, 배포본은 여러 모듈을 하나로 묶고 압축(minify)한 JavaScript 입니다. 프로세스 실행 코드와 압축된 코드가 함께 있어, 일부 백신의 휴리스틱(행위 추정) 검사에서 의심 파일로 분류될 수 있습니다. 이 경우 5번 방법으로 공식 배포본과 같은 파일인지 확인해 주시기 바랍니다.
